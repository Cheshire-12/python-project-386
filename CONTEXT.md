# Контекст проекта: Календарь звонков

Веб-приложение для записи на телефонные звонки по аналогии с Cal.com. Гость выбирает тип события и свободный слот, владелец управляет событиями и видит встречи.

## Словарь

- **Тип события (EventType)** — вид брони, который владелец предлагает гостям: название, описание, длительность в минутах. Название уникально. См. ADR-0004.
- **Встреча / бронирование (Booking)** — запись гостя на слот определённого типа события. Содержит имя (обязательно), телефон и email (опционально, могут быть null).
- **Слот (Slot)** — интервал в сетке расписания: `start`, `end`, флаг `available`. Вычисляется сервисом доступности, в БД не хранится. См. ADR-0002.
- **Сетка слотов** — расписание с шагом 30 минут; событие длиннее 30 минут занимает подряд идущие слоты. См. ADR-0002.
- **Свободный слот** — слот, на который ещё нет бронирования ни на одно время пересечения.
- **Конфликт слотов (SLOT_BUSY, 409)** — попытка создать бронирование на время, где уже есть бронирование любого типа события (та же сетка для всех типов). См. ADR-0002.
- **Окно записи** — ближайшие 14 дней от текущего момента (в MSK); вне окна бронирование отклоняется (422). См. ADR-0002.
- **Гость** — посетитель без аккаунта: смотрит типы событий, выбирает слот, создаёт бронирование.
- **Владелец / админ** — единственный предзаданный профиль без авторизации: CRUD типов событий, просмотр предстоящих встреч всех типов в одном списке.
- **Таймзона / MSK** — единая фиксированная таймзона календаря `Europe/Moscow` (= UTC+3, без перехода на летнее время). Все времена API передаются как UTC, отображаются в MSK. См. ADR-0001.
- **Контракт (Design First)** — спецификация API на TypeSpec: `typespec/*.tsp`. Из неё генерируются OpenAPI, JSON Schema и TS-типы клиента. См. ADR-0004.
