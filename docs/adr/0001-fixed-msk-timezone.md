# ADR-0001: Единая фиксированная таймзона Europe/Moscow

- **Статус:** принято
- **Дата:** 2026-09-01

## Контекст

Бронирование звонков чувствительно к локальному времени: слоты, «сегодня» и «окно записи» должны интерпретироваться единообразно для гостя и владельца. Календарь используется преимущественно в московском часовом поясе.

## Решение

Зафиксировать единую таймзону календаря `Europe/Moscow` (UTC+3):

- все времена в API передаются как `utcDateTime` (ISO 8601 с offset),
- сервер генерирует слоты и проверяет окно записи в MSK-наивном смысле — сетка начинается с локальной полуночи MSK,
- фронтенд отображает даты и время в MSK без выбора таймзоны пользователем.

Режим «зима/лето» не используется: Россия не переходит на летнее время, offset фиксирован (+3 круглый год).

## Последствия

- Реализация на фронтенде (RFC 0001) использует фиксированное смещение +3 часа вместо timezone-плагина dayjs — см. ADR-0006.
- На сервере окно бронирования считается от `datetime.now(UTC)`, слоты — от начала MSK-суток.
- Нет конфигурируемой таймзоны на клиенте; интерфейс показывает статичный текст «Europe/Moscow».
