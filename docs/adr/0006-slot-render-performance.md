# ADR-0006: Быстрый рендер слотов — отказ от timezone-плагина dayjs в горячем цикле

- **Статус:** принято
- **Дата:** 2026-09-08

## Контекст

После перевода интерфейса на MSK (ADR-0001) страница бронирования `/event-types/{id}` стала открываться с задержкой ~3.4 с (визуально «выбор даты/времени грузится 3–4 секунды»). Сеть и бэкенд были мгновенными: `/api/event-types/{id}/slots` отвечал за ~23 мс.

Диагностика: в `SlotPicker` для каждого дня календаря перебирались все ~672 слота окна, и для каждого вызывался `dayjs.utc(iso).tz('Europe/Moscow')`. Замер: 21 000 вызовов `.tz()` ≈ 6.3 с (обычный dayjs-parse ≈ 57 мс) — timezone-плагин дешёвым не является.

## Решение

1. **Мемоизация данных в `SlotPicker`:**
   - `slotsByDay: Map<дата, Slot[]>` — каждый слот конвертируется в MSK ровно один раз («слоты на выбранную дату» = `map.get(...)` вместо фильтрации по всем 672);
   - `availableDates: Set<дата>` — индикатор «есть слоты» на дне календаря по одному проходу.
2. **Фиксированное смещение вместо timezone-плагина** (`datetime.ts`):
   - `toMsk(iso)` = `dayjs.utc(iso).add(3, 'hour')`, `nowMsk()` = `dayjs.utc().add(3, 'hour')`;
   - плагин `dayjs/plugin/timezone` больше не используется (MSK без DST — ADR-0001).

## Последствия

- Загрузка календаря и слотов: **~3.36 с → ~160 мс** (замеры 152/165/171 мс).
- Домены времени не изменились: всё по-прежнему в MSK.
- Рекомендация: не помещать преобразования времени во вложенные циклы над всем окном слотов.
