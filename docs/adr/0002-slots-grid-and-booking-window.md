# ADR-0002: Сетка слотов 30 минут, окно записи 14 дней, глобальный конфликт

- **Статус:** принято
- **Дата:** 2026-09-01

## Контекст

Нужно чёткое доменное правило, как вычислять доступные времена и когда бронирование конфликтует с существующим.

## Решение

1. **Сетка:** слоты нарезаются с шагом 30 минут, начиная с 00:00 MSK. Событие длительностью > 30 минут занимает подряд идущие слоты (до `durationMinutes`).
2. **Окно записи:** бронирование возможно на ближайшие **14 дней** от текущего момента. Вне окна → ValidationError (422).
3. **Занятость/конфликт:** сетка общая для всех типов событий — на пересекающееся время нельзя создать бронирование **любого** типа события. Попытка занять занятый слот → 409 `ConflictError` c кодом `SLOT_BUSY`.
4. Слот помечается `available=false`, если пересекается хотя бы с одним бронированием.

## Последствия

- Сервер является источником истины: правила проверяются на бэкенде (`backend/services/slots.py`, `backend/services/validation.py`), а не только в UI.
- Фронтенд показывает только `available` слоты; конфликт, возникший в «гонке», отображается как понятное сообщение об ошибке («На это время уже есть бронирование»).
- Тесты покрывают: маркировку занятого слота, конфликт между разными типами событий, окно 14 дней.
